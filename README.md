# 街区警戒线

这是依据 `DEVELOPMENT_PLAN.md` 实现的浏览器游戏。生产入口由 React + Vite 构建，战斗画面继续由 Canvas 2D 驱动。

React 生产入口通过 Vite 按依赖顺序装载旧引擎模块；旧模块仍使用 `window.Game` 作为兼容层，便于现有专项脚本和 Canvas 渲染继续运行。React shell 负责挂载 Canvas，低频菜单与高频战斗界面统一交给完整旧 Canvas 界面；战斗实体、弹体、粒子和主循环仍留在游戏引擎内。`frontend/src/features/` 保留作为后续 React 界面切换的兼容层。

**账户与数据层（已实施）** 让项目成为全栈应用：`server/`（FastAPI + SQLAlchemy 后端，含 `run.py` 与 `requirements.txt`）持有 SQLite 数据库 `data/blockline.db`，账户、登录会话、关卡进度与资源全部落库；前端通过 `src/accounts.js` 与 React UI Store 访问同源 `/api`。设计与规则见 [`DEVELOPMENT_PLAN.md`](./DEVELOPMENT_PLAN.md) 第 12 节与第 19 节。

## 运行

### 全栈生产模式（推荐，React + 账户 + 进度）

```powershell
.venv\Scripts\pip install -r server\requirements.txt   # 首次执行
cd frontend
npm install                                           # 首次执行
npm run build
cd ..
.venv\Scripts\python server\run.py                     # 打开 http://127.0.0.1:8787
```

服务只绑定 `127.0.0.1`。存在 `frontend/dist/index.html` 时，FastAPI 返回 React 首页并托管 `/app-assets/`，同时继续提供 `/assets/`、`/pictures/` 与 `/api`；不存在构建产物时回退到旧版 `index.html`。首次访问可在首页账户入口注册或登录，数据库文件在 `data/blockline.db`（已在 `.gitignore` 中忽略）。换端口或换库：`python server\run.py --port 8790 --db tmp/other.db`。

### React 开发模式

分别启动后端与 Vite：

```powershell
.venv\Scripts\python server\run.py
cd frontend
npm run dev
```

浏览器访问 `http://127.0.0.1:5173/`。Vite 将 `/api`、`/assets` 和 `/pictures` 代理到 FastAPI，避免跨域并保持 Cookie 同源。修改 React 页面时使用此模式，不直接双击 `frontend/index.html`。

### 旧版离线模式（回退兼容）

直接双击根目录 [`index.html`](./index.html)，或通过静态文件服务器打开。该入口仍使用旧 Canvas 菜单与输入，账户功能不可用，成绩只保留在本次会话。React 迁移完成验收后，可再决定是否删除这条回退路径。

## 开发约定

- 新增敌人、词条、波次或平衡参数：优先修改 `src/config.js`。
- 新增僵尸时，在 `src/config.js` 的 `enemies` 中设置 `codexCategory`（`minion` / `elite` / `boss`）、`description` 和 `tactics`，首页僵尸图鉴会自动收录。
- 新增步枪强化时添加到 `traits`，核心技能升级项添加到 `skillTraits`，并为核心技能维护 `coreSkills` / `skillDefaults`。技能图鉴和升级池会自动收录配置中的词条。
- 新增战斗规则：放在 `src/combat.js` 或 `src/update.js`，不要写入渲染模块。
- 新增 Canvas 画面：放在 `src/render.js`，通过 `Game.state` 读取状态。
- 新增鼠标、触控或键盘操作：战场瞄准放在 `src/input.js`，React 页面按钮放在对应 `frontend/src/features/` 组件。
- 新增 React 页面：在 `frontend/src/features/` 创建组件，通过 `frontend/src/game/actions.js` 进入游戏命令层，通过 `frontend/src/game/ui-store.js` 获取低频快照；不要直接逐帧读取战斗实体。
- 新增旧引擎模块时，同步更新 `frontend/src/game/engine.js` 的导入顺序；长期目标仍是逐步改为 ES Module。
- 账户与进度：**只能经 `Game.accounts` 读写**（`src/accounts.js`）。`render.js` 只读缓存、不发起请求；`state.js` 的 `getProgress` / `markLevelComplete` / `isLevelCompleted` / `isLevelUnlocked` 是薄封装，不要绕过它们直接写 `localStorage`。
- 后端：依赖固定写进 `server/requirements.txt`；账户数据的唯一来源是 `data/blockline.db`；新增接口请在 `server/app/routers/` 下按模块添加，并在 `create_app()` 里挂载。
- 新增资源类型：在 `src/config.js` 的 `resources` 加条目，并同步 `server/app/config.py` 的 `RESOURCE_IDS`（服务端会拒绝未知资源）。
- 替换人物外观：更新 `assets/man.png` 后生成透明裁切图（`player-man.png` / `player-body.png`），并按新图比例调整 `src/config.js` 的 `sprites.playerBody` 宽高和锚点。
- 调整持枪位置：修改 `sprites.playerRifle` 的 `mountX` / `mountY`、宽高和锚点；`muzzleDistance` 应等于枪口到握把锚点的距离。
- 调整幻形位置：修改 `src/config.js` 的 `skillRing.offsetX` / `offsetY`。
- Canvas 使用逻辑分辨率绘制，并根据设备像素比自动提升实际渲染分辨率；调整画面尺寸时优先修改 `src/config.js` 的 `width` 和 `height`。

## 视觉实现

- `styles/main.css` 负责旧版页面容器、响应式比例和外层光晕；`frontend/src/styles.css` 负责 React 页面与浮层。React 根节点使用全屏 Flex 居中，宽屏浏览器下游戏与测试场面板保持水平居中，不会贴左显示。
- `src/render.js` 由 shell 模式下的完整 Canvas 界面接管视觉与界面：背景纵深、3D 金属城墙、分层人物精灵、悬浮幻形、僵尸模型、子弹拖尾、Boss 光效，以及菜单、HUD、升级和结算都由它绘制。`frontend/src/features/` 保留作为后续 React 界面切换的兼容层。
- 人物为分层 PNG：先绘制步枪（握把对齐左手），再叠加背影身体，使手和头部压住枪身；步枪随瞄准旋转，枪口与 `combat.js` 生成点对齐。
- 幻形悬浮在人物右上方、贴近右肩，避免与背包重叠。位置由 `src/config.js` 的 `skillRing.offsetX`（当前 64）与 `offsetY`（当前 -100）控制，同时也是核心技能的弹丸发射挂点。
- Canvas 使用逻辑坐标，并根据设备像素比提升实际渲染分辨率；业务逻辑不需要因为高清屏或 Canvas 尺寸变化而改写。

## 当前已实现

- **React 前端迁移（已实施）**：生产入口改为 React + Vite。React shell 负责挂载 Canvas，首页、关卡选择、僵尸 / 技能图鉴、登录注册、账户中心、属性、角色、装备背包、装备强化、宝石、城墙、战斗 HUD、暂停、升级三选一、结算和测试场工具统一由完整旧 Canvas 界面绘制；Canvas 继续负责战场、玩家、敌人、弹体、技能实体、粒子和伤害表现。旧引擎通过 `Game.mount()` / `Game.destroy()` 安全挂载，React 页面与 10 Hz 快照桥保留为后续可选切换。
- **账户系统（全栈）**：本地 FastAPI + SQLite 服务承载账户、登录会话、关卡进度与资源。首页菜单底部的「账户」按钮进入登录 / 注册界面（用户名 2–16 个中文 / 字母 / 数字 / 下划线，密码至少 6 位；密码以 PBKDF2-SHA256 加随机盐哈希存入数据库，**库里不存明文**，会话用 HttpOnly + SameSite=Strict Cookie，库中只存会话 token 的散列）。登录后进入账户中心：用户名、注册时间、通关进度、最近 5 关的最佳用时与击杀、资源区（金币 / 钻石 / 零件 / 六种部位图纸 / 钢材 / 稀土），以及「导入本机旧进度」「注销登录」「删除账户」（删除需重新输入密码）。**通关与失败都会上报**：胜利写入完成时间、刷新最佳用时 / 击杀并累加通关次数，失败只累加尝试次数，最佳值只取更优的一局。未登录或未连接数据库时顶栏提示「进度不会保存」，成绩只在本次会话内可见并在结算界面标注「成绩未保存」。

- 竖屏战斗画面铺满浏览器高度，战场随屏幕比例纵向拉伸（逻辑高度 640–960 自适应）；玩家、城墙与幻形贴近底部，战场更长。
- **角色属性（基础）**：新增 `Game.attributes` 作为角色属性的唯一计算层，基础值为攻击力 100、六系攻击力各 100、防线血量 1000、暴击率 8%、暴击伤害 150%、冷却缩减 0%、负面时间 100%。攻击力与六系攻击力是**数值、无上限**，伤害倍率按 `数值 / 100` 结算；后续装备 / 宝石 / 城墙分别通过 `Game.attributes.setModifiers`、`setGemModifiers`、`setWallHpBonus` 传入独立修正。攻击力作用于直接伤害与燃烧/冻伤 DPS，元素攻击按同属性结算，冷却缩减只作用于技能冷却，负面时间延长玩家施加的燃烧/冻伤/减速/硬控/重伤。首页改为左上角圆形账户按钮，中间为标题、开始战斗、选择关卡、进入测试场，底部为角色、技能图鉴、僵尸图鉴；角色界面汇总装备、宝石与背包（见下方「角色界面」），右上角「属性」进入只读属性面板。**装备系统已接入账号持久化**：六个部位（手臂 / 衣服 / 头盔 / 裤子 / 鞋子 / 手套）各一件，每件固定加攻击力，并在创建时随机分配一种元素攻击力；六件首次生成时洗牌分配六系、互不重复，之后元素固定。装备 Lv.1 起步、上限 **100 级**，每级攻击与元素各 +5（Lv.1 +10，Lv.100 +505）；升级消耗金币与对应部位专属图纸，图纸从 10 张起、每级 +10，金币从 80 起、每级 +40。装备数值通过 `Game.attributes.setModifiers` 直接加数字，角色界面与战斗结算同步。**装备背包**：关卡奖励掉落的装备只含部位与元素，进入背包后可在「角色 → 背包 · 装备」的方格逐件查看详情并直接换装，也可进入「角色 → 装备强化 → 装备背包」按部位挑选；**强化等级属于部位**，换装只交换元素、不损失等级；同部位同元素重复掉落照常保留，不自动折算。金币与图纸由关卡奖励产出，`/api/me/resources` 仍保留作调试 / 测试注入。
- **城墙材料（账号持久化）**：新增 `Game.wall`、`wall_state` 表与 `POST /api/me/wall/upgrade`。城墙 Lv.1 起步、上限 **200**，基础血量 1000、每级 **+200**（Lv.200 为 40,800）。钢材用于普通升级，消耗 `20 × 当前等级`；每 10 级（10/20/…/190）必须消耗稀土突破才能继续升级，第 N 次突破消耗 `2 × N` 稀土（2/4/…/38），**突破不改变等级、不增加血量**。城墙界面（入口：角色 → 城墙强化）显示等级、血量、下一节点与材料数量；普通等级只显示「强化」，到达 10/20/…/190 节点时同一张动作卡切换为「突破」。钢材使用灰白色长方体图标、稀土使用金色圆锥图标；账户中心资源区扩为 11 项、4 列 × 3 行。钢材 / 稀土由关卡奖励产出，界面提示已改为「关卡奖励产出」，`/api/me/resources` 仍可手动注入。
- **装备宝石（账号持久化）**：新增 `Game.gems`、`gems` 表与 `/api/me/gems/*` 接口。六件装备各有 **6 个槽位**，宝石按部位绑定，只有已镶嵌的宝石提供属性。品质由低到高为灰 / 绿 / 蓝 / 紫 / 红，每颗宝石带 1 条随机词条，词条覆盖攻击力、六系元素攻击、冷却缩减、防线血量、暴击率、暴击伤害与负面时间；品质只提高数值，不增加词条数量。宝石**不再自动合成**：主界面「一键合成」会先弹出确认窗口，列出全部可合成组（每组 5 颗同部位同品质未镶嵌宝石 → 1 颗高一档），点击任意宝石可预览词条，点「确定」才一次合成所有组，点「取消」不改动任何宝石；红色封顶，已镶嵌宝石不参与。新增**锁定机制**：背包行右侧锁按钮可锁定 / 解锁，锁定的宝石显示 🔒，不会被一键合成选中或消耗，仍可正常镶嵌。宝石管理全部并入角色界面：点击装备方块弹出该部位六槽位浮层（逐行显示品质、词条与「卸下」），背包「宝石」页签跨部位列出未镶嵌宝石（锁定 / 镶嵌 / 分页 / 一键合成），战斗结算会同步宝石加成。宝石由关卡奖励正式产出（灰 / 绿 / 蓝 / 紫四档，红色仍需五合一），`/api/me/gems/grant` 保留作调试 / 测试注入（可选 `affixId` 指定词条）。**镶嵌交互与词条约束**：点击背包里的宝石不再直接镶嵌，先弹出宝石详情（品质、词条、所属部位、槽位数与「镶嵌」按钮），点「镶嵌」才落位；同部位同词条只能存在一颗 —— 相同词条且品质不高于已镶嵌的那颗会被拒绝，更高品质则直接替换那颗宝石的槽位，槽位已满且词条不冲突时先弹出该部位六槽位浮层让玩家选择要替换的宝石（每行按钮变为「替换」），点「关闭」取消。账户资源中的 `gem` 是货币「钻石」，与新宝石系统分开。

- 解锁后，幻形自动发射红色温压弹和蓝色圆锥干冰弹；温压弹基础冷却 5 秒，命中后产生冲击、击退、范围爆炸与燃烧，干冰弹基础冷却 3.5 秒且初始可额外穿透 3 个目标。每个技能解锁显示 Lv.1，之后每取得一个相关词条提升 1 级。拿到**干冰冻伤**后，干冰弹每次命中还会为目标叠加 1 层冻伤（每层每秒 1.5 点、持续 5 秒、最多 10 层，分裂小冰弹照常继承；详见「负面状态」一节）。
- 装甲车（解锁词条名为“装甲车支援”）解锁时立即派出首辆，之后每 6.3 秒从城墙前方随机车道驶出，沿途碾过敌人并施加减速；**初始车身 42×80、车速 100、每 0.12 秒结算一段 4 点伤害**，一只静止僵尸停在车下会被碾压 9 段（改动前为 34×64 / 速度 140 / 0.16 秒 / 4~5 段）。车速降下来、车身变大之后，同一只僵尸在车下的停留时间从 0.69 秒拉长到 1.12 秒，碾压覆盖面积增加 54%。命中间隔刻意保持在护甲格挡窗口之上（两者同为 `config.armorBlockWindow` 0.12 秒），因此**每一段都能扣掉一层装甲**：一趟就能剥光护甲僵尸的 6 层装甲并接着打出实际伤害，而改动前一趟只剥 5 层、整趟一点血都打不掉。眩晕、车数、伤害、减速时长与车身尺寸仍可通过专属词条强化。车辆伤害不继承步枪燃烧/冰冻效果，击杀仍会触发分裂、经验和击杀结算。

- 电磁穿刺解锁后自动从天而降闪电劈向接近防线的目标，基础冷却 3 秒，造成伤害并麻痹；电磁分流最多 4 级，每级额外选定 1 个目标；还可通过电磁增伤、电磁爆炸、麻痹增伤和电磁矩阵强化伤害、范围伤害、麻痹时长与持续减速伤害。

- 步枪与核心技能都有**交战距离**：僵尸进入对应距离后才会开火或释放，进入前保持待机（冷却已就绪也不会空转）。距离以城墙攻击线为基准配置在 `config.ranges`：远 480、中 320、近 125 像素。远距离为步枪、高能射线、装甲车、空投轰炸；中距离为温压弹、干冰弹、电磁穿刺、旋风加农、冰雹发生器、压缩气刃、无人机、跃迁电子；近距离为燃油弹。测试场会画出这三条距离线，正式关卡不显示。

- **伤害属性**：每个伤害来源都带一项数据层属性 —— **物理、能量、电、冰、火、风**。步枪默认为物理，拿到**冰冻弹**后变为冰、**燃烧弹**后变为火；**装甲车、空投轰炸、无人机**为物理，**压缩气刃、旋风加农**为风，**温压弹、燃油弹**为火，**干冰弹、冰雹发生器**为冰，**跃迁电子、电磁穿刺**为电，**高能射线**为能量。属性会随弹体、火场、龙卷风、无人机、炸弹、热核区与电磁矩阵等实体一起快照，命中时记录在敌人身上；**技能图鉴**的列表与详情页会按属性配色显示「N 属性」徽标（步枪一行额外标注「冰子弹为冰属性 · 火子弹为火属性」）。

- **负面状态分四类**：**伤害性**（燃烧、冻伤，持续掉血）、**软控**（减速、击退、牵引，限制移动但不打断攻击）、**硬控**（眩晕、冻结、麻痹）、**削弱**（重伤，压制回血）。**硬控期间敌人完全无法移动与攻击** —— 被冻住的僵尸既不前进也不啃墙，被麻痹的篮球僵尸也不会投出篮球。三种硬控机制等价、只是来源与配色不同：**眩晕**来自装甲车冲撞、空投轰炸震荡与无人机撞击，**冻结**来自冰系技能，**麻痹**来自电磁穿刺与跃迁电子；三者共用同一个控制计时（先来后到，更长的控制接管并决定头顶标记「晕 / 冻 / 麻」与虚线环颜色），**冻结**还会给僵尸套上一层半透明冰壳（战场上的减速仍是原来的细蓝虚线环）。**击退是瞬时位移而不是持续状态**：温压弹命中与爆炸、空投轰炸（含中心以外的衰减）、干冰弹及其分裂小冰弹、压缩气刃都会把目标沿背离爆心/弹道的方向推开，被推开的僵尸**照常推进与攻击**，只是被推远了一截。**牵引同样是叠加在推进之上的位移**：旋风加农的龙卷风每帧把风圈内的敌人朝风眼拉 `pullSpeed × dt × 距离衰减` 像素，走软控的第三条状态 `pull`（`Game.applyPull`），同样不打断推进与攻击，但会被状态免疫、倍率缩放与护甲格挡 —— **寒霜兽与寒霜兽精英免疫这条状态，站在风眼里也一步不动**（伤害照常结算）。**冻伤是叠层持续伤害**：干冰弹的「干冰冻伤」与冰雹发生器的「冰雹冻伤」两条 1 级词条让每次命中 / 每次砸击叠 1 层 —— 每层各自持续 5 秒、最多叠 10 层，**每秒造成的伤害 = 单层伤害 × 当前层数**（干冰弹每层 1.5 点、冰雹每层 1.2 点，各自叠满则是 15 点/秒与 12 点/秒）；两个来源**分别记层、各自计时**，干冰弹的层到期不会带走冰雹的层，叠满后再命中会把剩余时间最短的一层刷新为满时长。与燃烧一样，冻伤按秒掉血、吃致残射线的加成、**不吃属性倍率**（雪人僵尸的冰系减半与火焰僵尸的冰系 ×1.5 都不影响它），敌人被硬控期间也照常结算。**两种伤害性状态都有战场角标**：燃烧中的僵尸在血条右侧画橙色的「燃」，有冻伤的僵尸紧接着画蓝色的「霜」+ 总层数（例如「霜10」，两个来源的层数相加），角标没有该状态时就不画；位置与护甲僵尸的「甲 N」角标分居血条两侧，贴屏幕边缘时也会被夹回画面内。
- **冻结是硬控，不是减速**：冰系技能在减速之外额外把目标**定身** —— 冰雹发生器每次砸击冻结 0.6 秒（0.25 秒一跳，区域内基本一直定住）、冰霜爆炸把范围内敌人冻结 1.5 秒（替换了原来的 ×0.22 / 2.5 秒强减速）、干冰弹的「冰冻」词条每级 +0.5 秒冻结时长、步枪**冰冻弹**命中后冻结 0.35 秒（只在冰子弹且点出该词条时生效）。这些时长刻意压得比旧的减速时长短：硬控是完全停住，直接沿用 1.1～1.2 秒会让冰雹和步枪把单体永久锁死。
- **状态抗性**：除了属性倍率，敌人还能声明**负面状态的免疫与缩放** —— `config.enemies[].statusImmune`（例如火焰僵尸的 `{ burn: true, freeze: true }` 表示完全免疫燃烧与冻结）与 `statusDurationScale`（例如雪人僵尸的 `{ freeze: .5 }` 表示冻结时间减半、**雷电僵尸**的 `{ paralysis: .5 }` 表示麻痹时间减半），统一由 `Game.getStatusScale(enemy, status)` 读取，所有负面状态入口（`applySlow` / `applyKnockback` / `applyPull` / `applyStun` / `applyFreeze` / `applyParalysis` / `applyBurn` / `applyFrostbite` / `applyWound`）在写字段前先查它：倍率为 0 时直接返回，既不写状态字段也不消耗护甲层数，调用方无需特判。**击退没有持续时长，倍率乘的是推开距离**（`{ knockback: .5 }` = 只推开一半），图鉴里因此显示为「软控·击退距离 −50%」而不是「击退时间」。注意**免疫冻结不等于免疫减速**：火焰僵尸免疫的是硬控，装甲车的碾压减速与冰雹的减速照常生效，它也会被眩晕与麻痹。**雷电僵尸只针对麻痹**：小怪麻痹时间减半、精英则用 `statusImmune: { paralysis: true }` 完全免疫麻痹，两者都照样会被眩晕与冻结，也照样吃减速、燃烧与重伤。**击退与牵引同样可以免疫**：寒霜兽与寒霜兽精英的 `statusImmune` 里同时带着 `knockback: true` 与 `pull: true`，压缩气刃、温压弹与空投轰炸推不动它们，旋风加农的龙卷风也拉不动它们（在它们之前，只有护甲僵尸的装甲能挡下这两条位移）；**牵引是软控的第三条状态**（`config.statusEffects.pull`，入口 `Game.applyPull`）：与击退同构，先查 `getStatusScale` 再被护甲格挡，倍率缩放的是**牵引速度**（图鉴里因此显示「软控·牵引速度 −50%」而不是「牵引时间」，不过这条倍率分支目前还没有单位使用）。状态名称、分类与配色集中在 `config.statusEffects` / `config.statusCategories`，僵尸图鉴新增「状态抗性」一行按分类前缀展示（「伤害·免疫燃烧」「硬控·免疫冻结」「硬控·冻结时间 −50%」「硬控·免疫麻痹」「软控·免疫击退」「软控·免疫牵引」）。

### 当前步枪词条规则

- **齐射**：增加带角度差的弹道；相邻弹道角度间隔为 0.12 弧度（步枪齐射、干冰弹齐射与压缩气刃齐射共用），齐射等级越高，扇形覆盖越宽。自动和手动瞄准会锁定一条实际弹道，不会瞄准两条弹道的角平分线。
- **连发**：步枪每次攻击沿同一条弹道按短间隔连续发射额外子弹；子弹在运动方向上前后排列，而不是同时横向生成。温压弹和干冰弹每次连发都会重新索敌，并优先选择与本轮已发弹方向差异较大的目标；压缩气刃同样每轮重新索敌，没有其他方向的目标时仍会攻击可用目标。
- **齐射 + 连发**：每一轮连发都会按当前齐射等级发射分角弹道。
- **弹药消耗**：每次基础攻击周期只消耗 1 发；齐射产生多条弹道、连发追加子弹均不额外扣除弹药。最后一发的连发完成后开始换弹。
- **燃烧弹 / 冰冻弹**：分别切换为橘色 / 蓝色子弹，并附加持续伤害 / 减速效果。
