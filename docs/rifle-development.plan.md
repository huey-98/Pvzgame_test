# 步枪图纸与等级系统开发计划

> 本文只记录步枪账户成长系统的设计草案和执行计划，尚不改变任何运行规则。
> 实施前请先和现有 README / DEVELOPMENT_PLAN 中的装备、技能、资源模型核对，避免口径重复。

## 1. 定位与目标

步枪账户成长是长期存档成长路径，不同于局内三选一构筑。

目标:

1. 步枪等级不设上限。
2. 每升 1 级，步枪最终伤害提升 5 点。
3. 步枪以专属图纸作为升级材料。
4. 新增少量高等级里程碑，用于解锁步枪新机制。
5. 账户等级与局内构筑词条分开保存、分开显示、分开结算。
6. 服务端是等级、扣费、材料校验的唯一权威。

本系统不应混入 `skill_progress`。它使用独立的步枪成长层，避免和 12 个核心技能的等级、里程碑、冷却与伤害成长互相污染。

## 2. 核心规则

### 2.1 等级与伤害

- 等级字段只保存整数 `level`，另加账户外键。
- 等级下限为 `1`，不设最大等级。
- 出生即 Lv.1。
- 为避免未升级账户获得额外伤害，实际加成从 `Lv.2` 起结算。
- 步枪基础伤害为 `28`。
- 步枪最终基础伤害为 `28 + 5 * (level - 1)`。
- 该伤害只作用于步枪直接命中伤害。
- 局内增伤词条、暴击、燃烧、冰冻、齐射、连发、穿透等继续在最终伤害之上独立结算。

示例:

| 等级 | 基础伤害 |
| --- | ---: |
| 1 | 28 |
| 5 | 48 |
| 14 | 93 |
| 24 | 143 |
| 36 | 203 |
| 52 | 283 |

### 2.2 局内构筑与账户成长

局内 `player.traits` 继续表示本局三选一获得的步枪词条等级。

账户 `rifle_progress.level` 表示永久步枪等级，只影响本局快照，不写入局内词条等级。

登录后，客户端把步枪等级转换为本局战斗快照。快照只在其匹配的步枪伤害结算里生效，不会写入全局攻击力或其它角色属性。

### 2.3 高级节点

高级节点完全由等级推导，不在数据库中单独保存。

| 等级 | 节点 | 效果 |
| --- | --- | --- |
| 4 | 分裂子弹 | 子弹命中后分裂 2 个次级子弹。 |
| 14 | 快速换弹 | 换弹时间 ×0.94。 |
| 24 | 射速解锁 | 解锁原有“射速”词条。 |
| 36 | 火力同步 | 射击间隔额外 ×0.96。 |
| 44 | 子弹弹射 | 子弹命中战场边缘后弹射一次。 |
| 52 | 战术穿透 | 子弹初始穿透 +1。 |

注:

1. 高级节点不占用局内三选一槽位。
2. 达成等级后自动解锁。
3. 分裂子弹与子弹弹射属于新步枪机制，不使用核心技能的 `progressSkillId` 语义，只在步枪账户成长层挂接。
4. “射速解锁”是对现有局内词条的门禁，不是新增第三条射速路线。

## 3. 客户端

### 3.1 配置

`src/config.js` 添加 `rifleProgress`。建议结构:

```js
rifleProgress: {
  baseDamage: 28,
  damagePerLevel: 5,
  coinBase: 200,
  coinPerLevel: 60,
  blueprintPerLevel: 10,
  blueprintId: "rifleBlueprint",
  milestones: [4, 14, 24, 36, 44, 52],
}
```

另需 `rifleProgressTraits` 或等价结构，按等级记录节点名称和效果描述。

### 3.2 成长层

建议新增 `src/rifle.js` 或类似只读层。

职责:

1. 应用账户返回的步枪等级。
2. 计算当前最终基础伤害。
3. 推导已解锁节点。
4. 清理登出 / 401 / 离线状态。
5. 提供战斗快照入口。

不应处理:

1. 网络请求；这些仍由 `accounts.js` 负责发起。
2. Canvas 绘制。
3. 弹道移动、命中、伤害或局内词条应用。

### 3.3 战斗接入

`combat.js` / `state.js` 负责实际行为:

1. 用步枪等级计算本局最终基础伤害。
2. 实现节点对应的弹头分裂、弹射、穿透、射速与换弹效果。
3. 继续走 `Game.damageEnemy`。
4. 保留现有元素、属性、暴击、燃烧、冻伤、抗性结算。
5. 保留“每个基础攻击周期扣 1 发弹药”的规则。

测试场固定 Lv.1 快照，正式关卡读取真实账户等级。

### 3.4 界面

建议复用现有技能图鉴 / 角色强化页样式:

1. 步枪分组详情页显示当前等级。
2. 显示伤害加成、下一级消耗、材料库存。
3. 显示 6 个高级节点与解锁状态。
4. 提供“强化”按钮。
5. 未登录或离线时不发请求，只展示状态。

React 兼容层同步:

1. `frontend/src/game/ui-store.js` 输出步枪成长快照。
2. `frontend/src/game/actions.js` 暴露升级命令。
3. `frontend/src/features/` 中的账户 / 角色 / 图鉴界面同步显示。

## 4. 数据服务

### 4.1 数据库

新增 `rifle_progress` 表:

```text
account_id  primary key, foreign key to accounts.id, cascade delete
level       integer, default 1
```

旧账户无需手工迁移。新账户和旧账户在 `/api/me` 时幂等补齐 Lv.1。

### 4.2 资源

新增资源 ID:

```text
rifleBlueprint
```

该资源独立于六种装备部位图纸、12 种技能专属图纸、钢材、稀土、金币、钻石和零件。

### 4.3 升级接口

新增 `POST /api/me/rifle/upgrade`。

响应建议:

```json
{
  "rifle": {
    "level": 4,
    "damage": 43,
    "milestones": [4, 14, 24, 36, 44, 52],
    "unlockedMilestones": [4],
    "nextCost": {
      "coin": 200,
      "rifleBlueprint": 10
    }
  },
  "resources": {}
}
```

服务端不接受客户端传来的等级、伤害或节点状态；只基于当前账户行更新一个整数等级。

### 4.4 升级消耗草案

金币:

```text
200 + 60 * (当前等级 - 1)
```

步枪图纸:

```text
10 * 当前等级
```

示例:

| 当前等级 | 强化后 | 金币 | 步枪图纸 |
| --- | ---: | ---: | ---: |
| 1 | 2 | 200 | 10 |
| 10 | 11 | 740 | 100 |
| 50 | 51 | 3140 | 500 |

实际价格、图纸数量和奖励产出需要后续用关卡资源脚本统一测算。

## 5. 关卡奖励

每局结算中加入步枪图纸产出。

建议:

1. 普通结算按已到达档位追加少量步枪图纸。
2. 通关可追加额外步枪图纸。
3. 数量先放进服务端配置，后续按无上限等级的成长节奏调整。
4. 结算 UI 需要把步枪图纸和部位 / 技能图纸分开显示。

实施时需要更新 `tmp/check-rewards.js`，确认步枪图纸进入资源白名单、数据库正确落库、未登录 / 离线不发奖，并且不会被误计入部位图纸或技能图纸统计。

## 7. 验证

至少执行:

```powershell
npm --prefix frontend run build
node tmp/check-react-ssr.mjs
Get-ChildItem src -Filter *.js | ForEach-Object { node --check $_.FullName }
git diff --check
```

按改动范围追加:

```powershell
.venv\Scripts\python -m compileall server
.venv\Scripts\python tmp\check_db.py
.venv\Scripts\python tmp\check_api.py http://127.0.0.1:8787
```

专用与新规则检查:

```powershell
node tmp/check-rifle-progress.js
node tmp/check-rifle-balance.js
node tmp/check-rewards.js
node tmp/check-skills.js
```

重点验证:

1. 等级无上限。
2. Lv.1 不额外增加伤害。
3. 等级越高，最终基础伤害越大。
4. 六个高级节点按等级解锁。
5. Lv.24 前升级池不给射速，Lv.24 后恢复。
6. 分裂子弹、弹射和穿透不会破坏护甲格挡、属性抗性、命中记录或伤害来源快照。
7. 测试场固定 Lv.1。
8. 登录、登出、401、离线、刷新不会污染本地结果。
9. 服务端升级成功扣费；失败不扣费且等级不变。
10. 关卡奖励写入 `rifleBlueprint`，结算统计不误分类。

Canvas 画面使用:

```powershell
tmp\trace-draw.js ... 
tmp\replay-draw.py
```
